# Decision log

Records accepted review recommendations (REVIEW.md, 2026-10-05) and their rationale. Package version 2.0.0-draft → 2.1.0-draft. Prior text is preserved in this log rather than silently overwritten.

| ID | Decision | Rationale | Replaces |
|---|---|---|---|
| DEC-01 | The product is an **allele nomination** tool: nominate new alleles for the next variant-level screen, transferable across genes and diseases. Default ranking profile is `nomination_v0.1`. | Owner decision. An evidence-recovery ordering favours alleles that are already characterized, which is the opposite of what a screen needs. | `evidence_priority_v0.1` as default; it is kept only as an evaluation baseline ("known-evidence recovery") |
| DEC-02 | An allele with an accepted exact-allele functional experiment is `characterized`. By default its primary channel is `control` (role `positive_control_candidate` if the outcome is `altered`, `characterized_other` otherwise). Configurable per run. | Re-testing known alleles is useful as a control, not as discovery. No-effect results are not converted to benign. | F tier as a discovery sort key |
| DEC-03 | Add a class-level mechanism-concordance key **K** derived from a per-gene `GeneMechanismAssessment` (LoF/haploinsufficiency, gain-of-function, dominant-negative, mixed, unknown) resolved from structured sources, and a declared concordance table (mechanism × variant class → concordant / partial / discordant). Unknown mechanism → K is `not_assessable` for every allele and reported as degenerate. | The mechanism decides which variant classes can perturb the gene in the disease-relevant direction; this is what makes the tool transfer across genes (a GoF gene inverts the LoF preference). K is labelled inferred/class-level and never becomes exact-allele evidence (R-09 preserved). | Phase 0 numeric `mechanism_gating.yaml` multipliers |
| DEC-04 | Rank **within consequence stratum**. Cross-class allocation is the job of a separate panel step with declared quotas. | Predictors differ by class; a pooled order has no common scale. Makes the cross-class trade-off explicit. | SPEC §8.2 pooled tuple |
| DEC-05 | Ties are reported as ties: dense tier rank, explicit tie-group IDs and sizes, display order by genomic coordinate. No hash tie-break. Each sort key reports whether it was degenerate in the run. | A hash tie-break presents arbitrary order as a ranking and reshuffles when identity conventions change. | `variant_id` tie-break |
| DEC-06 | Prediction key **P**: one declared predictor per consequence class; raw value used only for ordering within that class; missing/unsupported sorts after every present value and is flagged, never treated as 0. | Within one predictor, ordering is meaningful; across predictors it is not. | — |
| DEC-07 | Observation key **O**: `case_controlled` (exact allele in an approved disease cohort with a control denominator available) > `case_uncontrolled` > `related_condition` > `none`. ClinVar clinical classifications are exported but are not in O. | A single case carrier without a denominator is weak; disease anchoring for nomination comes mostly from gene-level evidence that the gene is a risk gene, which is the input, not a per-allele key. | D tiers |
| DEC-08 | Evaluation: primary cross-gene benchmark from MAVE/DMS (and saturation genome editing) readouts — can the nominated top-k recover alleles with measured effects, with genes held out; SETD1A scPRIME as a retrospective case study; ClinVar P/LP only as a lookup baseline. | Owner requires ground truth; DMS gives per-allele labels across many genes. | EVAL B1 as the main benchmark |
| DEC-09 | Implementation evolves the `tessera` package. Phase 0 weighted composite (anchors, weights, novelty multiplier, saturation) is archived to `archive/phase0/`. `Strict`, missingness semantics and the degeneracy diagnostic idea are carried forward. | Owner decision; avoids two codebases. | `src/variant_agent/` layout |
| DEC-10 | M1 split: **M1a** structured sources only, no LLM, real-gene run; **M1b** literature/GEO workers. | Restores the deterministic real-data milestone; defects like S2 only appear on real numbers. | single M1 |
| DEC-11 | M0 identity accepts genomic (VCF-style) alleles only, normalized against a synthetic FASTA; HGVS c./p. mapping arrives in M1a with real GRCh38/MANE resources. | Reference-aware HGVS libraries need real transcript resources. | ISSUE-002 HGVS scope in M0 |
| DEC-12 | Source plan adds AlphaMissense (local tables), a SpliceAI-class splice predictor, ClinGen dosage sensitivity, gnomAD constraint, Gene2Phenotype mechanism, MaveDB (eval). AVI and AlphaMissense are never used as two independent keys. | AVI includes AlphaMissense (verified 2026-10-05). | — |
| DEC-13 | M0 store is a content-addressed JSONL file bundle; SQLite repositories and stage checkpoints arrive with M1b. | M0 has no network, no LLM, no retries; checkpoints add cost without exercising anything. | ISSUE-003 SQLite in M0 |
| DEC-14 | Correction to DEC-03: because ranking is within stratum, class-level concordance is constant inside a stratum. K therefore uses declared sub-class features (PTV NMD status; missense/in-frame domain membership) within a stratum; class-level concordance is reported per stratum and feeds panel quotas. | Found while implementing: a class-only K would be degenerate in every stratum by construction. | DEC-03 within-stratum wording |
| DEC-15 | M1a sources (verified live 2026-10-05): Ensembl REST release 116 for gene/MANE lookup, chromosome RefSeq accession, reference slice and VEP (consequence, HGVS, AlphaMissense, SpliceAI, LOFTEE); gnomAD r4 GraphQL for frequency/constraint; SCHEMA results browser REST for per-allele case/control **allele** counts (O) and gene burden; ClinVar E-utilities for candidates/classification; UniProt for protein regions; ClinGen dosage TSV. VEP AlphaMissense agreed with the local AlphaMissense table on all 1,097 SETD1A missense alleles. | One structured, versioned source per field; VEP does not validate REF, so tessera does. | — |
| DEC-16 | `mechanism_rule_v0.1` (provisional): ClinGen HI score 3 → loss_of_function; otherwise disease-cohort PTV burden p ≤ `burden_max_p` (default 2.5e-6, owner to confirm) with OR > 1 → loss_of_function; otherwise unknown. Constraint (LOEUF/pLI) is recorded as basis but never decides. | Constraint means intolerance, not mechanism (SCHEMA §2.5). | — |
| DEC-17 | `in_functional_domain` = residue inside a UniProt Domain, Motif, or "Interaction with …" Region; used only when the UniProt sequence equals the MANE protein sequence, else not_available. | Declared, auditable rule; isoform mismatch must not silently map residues. | — |
| DEC-18 | SCHEMA `in_analysis=false` does not block O; the flag is kept in the claim text. Its exact meaning was not verified (pattern suggests "variant class not used in the burden test", not QC failure). | Avoid inventing a QC interpretation; owner/reviewer to confirm. | — |
| DEC-19 | Known recall gap: by protein-level matching, 8 of the 18 existing scPRIME SETD1A panel alleles are not reachable from ClinVar + SCHEMA case observations. Literature discovery (M1b) or manual input is required to cover them; protein-level matching is approximate and is not used in the pipeline. | Candidate discovery must be evaluated, not assumed (EVAL §5). | — |
